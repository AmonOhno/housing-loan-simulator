# 住宅ローン概算シミュレータ

住宅ローンの返済額・資金計画（申込書の記入イメージ）・ケース比較・繰上返済・住宅ローン控除を**概算**するための静的 Web アプリです。ビルド不要（HTML／CSS／バニラ JavaScript の ES モジュール）、外部 CDN・外部フォント・解析タグなし、入力内容は外部に送信されません。

- 公開 URL: https://amonohno.github.io/housing-loan-simulator/
- すべて概算です。実際の返済額・審査結果は金融機関の返済予定表で確認してください。

## 使い方

1. 「物件・資金（共通）」に物件価格・諸経費（一括保証料を除く）・手付金・税込年収・返済開始年月を入力（金額は万円）。
2. 「借入条件（ケース）」でケースごとに借入額・金利・期間・返済方式・ボーナス返済分・保証料方式・繰上返済を入力。ケースは最大 3 件まで追加・複製・削除できます。入力のたびに自動で再計算されます。
3. 結果サマリー、資金計画チェック（必要資金＝調達資金の左右一致）、ケース比較（基準ケースとの月額・総利息などの差額）、残高推移グラフ（タップで年末残高）、住宅ローン控除、年次返済予定表を確認します。
4. 手付金を頭金に回す（借入を少なくする）ケースと、手付金分も借りる（借入を多くする）ケースは、借入額だけを変えた 2 ケースで比較できます。手付金は自己資金の内訳として扱い、物件価格からは差し引きません。
5. 入力途中の不正値には赤字のエラーが出て、直るまで前回の有効な結果を表示します。

## 計算の前提

- 元利均等・元金均等。金利は全期間一定。毎月返済額・利息は円未満切り捨て、最終回で残高を精算。
- ボーナス返済は借入額のうちボーナス返済分（借入額の 50% 以内）を半年利率（年利÷2）で 6 か月ごとに返済。
- 保証料は金利内包型（金利に上乗せ、初期値 0.2%）／一括前払型（100 万円あたりの目安表から自動算出、手入力可）／なし。いずれも一般的な目安であり、金融機関の提示額に置き換えてください。
- 返済負担率は初年度 12 か月の返済額 ÷ 税込年収で、審査上の値とは一致しません。
- 繰上返済は期間短縮型・返済額軽減型。毎月分とボーナス分に残高比で按分します。手数料・保証料返戻は扱いません。
- 詳細は `docs/requirements.md`（要件）と `docs/implementation-plan.md`（実装計画）を参照。

## 住宅ローン控除の前提と出典

令和 8 年度税制改正後（2026〜2030 年入居）の制度値を `js/data/deduction-table.js` に集約しています。控除率 0.7%、控除期間は区分により 13 年または 10 年、借入限度額は取得の種類・省エネ性能区分・子育て世帯等の該当で選択します（すべて画面から手入力で上書き可）。所得税・住民税の頭打ちは、任意入力の所得税額と住民税上限（初期値 9.75 万円）による簡易処理です。

- 確認日: 2026-11-15
- 出典: 国土交通省「住宅ローン減税」、同「住宅ローン減税 Q&A」（居住開始が令和 8 年 1 月 1 日以降）、総務省「個人住民税の住宅ローン控除」ほか（画面と `docs/requirements.md` 9 章に URL を記載）

未確認・要確認事項:

- 既存住宅の ZEH 水準の限度額、買取再販の省エネ基準適合住宅の 2028 年以降入居の扱いは要確認（画面にも表示）。
- 国土交通省の改正概要（別紙 1）・適用要件確認チャートは画像主体で読み取れず未確認。
- 所得・床面積・証明書類などの要件は判定しません。最新の制度は国土交通省・国税庁で確認してください。
- 子育て世帯等の判定は入居した年の 12 月 31 日時点です。

## マイ設定（パスワード保護された設定セット）

パスワードで暗号化した入力値セット（共通項目＋全ケース）を保存・読み込みできます。暗号方式は Web Crypto API の PBKDF2-SHA256（60 万回）で鍵導出し、AES-GCM-256 で暗号化します（ソルト・IV はランダム）。パスワードのハッシュは保存せず、復号できるかどうかだけで判定します。リポジトリには暗号文のみを置きます。オーナー用の暗号化済み設定セットを 1 件同梱する運用です。

### 使い方

- 「マイ設定」→「保存済みの設定を使う」でパスワードを入力すると、同梱分とこの端末（localStorage）に保存した分のうち、復号できる設定が一覧表示されます。「入力欄に反映」で共通項目と全ケースが入力欄に入り、「現在の入力で上書き保存」でその設定を現在の入力内容に置き換えてこの端末に保存します。どちらも完了するとマイ設定を閉じてメイン画面に戻り、画面上部に完了の通知が出ます（「現在の入力を新規保存」「別の名前で追加保存」も同じ）。
- 入力欄の値そのものは自動保存しません。
- 入力欄にエラーがある間は、「現在の入力を新規保存」「現在の入力で上書き保存」「追加保存」はできません（エラーのある値を既定値で補って保存することはしません）。
- **同梱とこの端末の優先関係**: 同梱のエントリを画面で編集して保存すると、同じ id でこの端末（localStorage）に保存されます。その端末では端末側の版が優先して開かれ、エクスポートして `data/presets.enc.json` を更新・コミットするまで、他の端末には古い同梱版が表示されます。端末側に同じ id の版があるときに同梱版を保存しようとすると、上書きの確認が出ます。

### 新しい設定セット＋パスワードの追加

1. 画面で入力を整え、「マイ設定」→「新規作成」で名前と新しいパスワードを入れて「暗号化してこの端末に保存」。localStorage に暗号化したまま保存されます。
2. 全端末で使うには「エクスポート」→「全体形式をダウンロード（またはコピー）」し、`data/presets.enc.json` を置き換えてコミットします。
   平文 JSON を自分で用意するより、**画面で作成してエクスポートする方法が最も簡単**です。
3. 既存エントリへの追加・上書き・名前変更・削除は、解錠して操作するとその場でこの端末に保存されます（保存に失敗したときだけ「保存をやり直す」が表示されます）。必要ならエクスポートして同様にコミットします。

### CLI（scripts/encrypt-preset.mjs）

パスワードは環境変数 `PRESET_PASSWORD` か標準入力 1 行目で渡します（引数では受け取りません）。平文はファイルに書かない運用を推奨します。

```bash
read -rs PRESET_PASSWORD && export PRESET_PASSWORD
# 平文 JSON を貼り付けて Ctrl-D。既存コンテナに追加
node scripts/encrypt-preset.mjs --merge data/presets.enc.json
unset PRESET_PASSWORD

# 復号できるエントリの確認（平文は表示されない）
read -rs PRESET_PASSWORD && export PRESET_PASSWORD
node scripts/encrypt-preset.mjs --check data/presets.enc.json
unset PRESET_PASSWORD
```

`--replace-id <id>`（同じ id で置き換え）、`--entry-only`、`--iterations <n>` も使えます。平文 JSON の形式は `docs/requirements.md` 10.4。

- `--replace-id` に渡す **id は `--check` で確認**できます（`復号できたエントリ: id=...` と表示されます）。
- 最小の平文 JSON の例（ダミー値）: `{"sets":[{"name":"例","cases":[{"label":"A","loan":3500}]}]}`（省略した項目は既定値で補われます。単位は万円など画面と同じ）。
- 平文 JSON をターミナルに貼り付けると、スクロールバックや履歴に残ることがあります。作業後は端末の表示を消去（`clear`）してください。

### パスワード変更（再暗号化）

- 画面: 解錠 → 該当エントリの「パスワード変更（再暗号化）」→ 新しいパスワードで保存 → エクスポート → `data/presets.enc.json` を更新してコミット。
- CLI（平文不要）: パスワードが画面や履歴に残らないよう、`read -rs` で環境変数に入れてから実行します。旧パスワードで復号できるエントリがすべて、同じ id のまま新パスワードで再暗号化されます。

  ```sh
  read -rs PRESET_PASSWORD && export PRESET_PASSWORD          # 旧パスワード（表示されません）
  read -rs PRESET_NEW_PASSWORD && export PRESET_NEW_PASSWORD  # 新パスワード
  node scripts/encrypt-preset.mjs --rekey data/presets.enc.json
  unset PRESET_PASSWORD PRESET_NEW_PASSWORD
  ```

  （環境変数を使わない場合は標準入力の 1 行目に旧、2 行目に新パスワード。`PRESET_PASSWORD` だけ設定した場合、新パスワードは標準入力の 2 行目から読まれる点に注意。）
- CLI（平文から作り直す場合）: 平文を用意し、新しいパスワードで `--merge data/presets.enc.json --replace-id <id>`。

### セキュリティ上の注意

- 暗号文は公開リポジトリに置かれるため、誰でも入手してオフラインで総当たりできます。**4 桁の数字など短いパスワードは容易に破られます。**8 文字以上の英数字混在（できれば長いパスフレーズ）を推奨します。画面では弱いパスワードに警告を出します。
- 一度コミットした暗号文は git 履歴に残ります。パスワードを変更しても、過去の暗号文は古いパスワードで復号できます。
- パスワードを忘れた場合、復元する手段はありません。
- パスワード・平文の設定値をコード・テスト・ドキュメント・コミットメッセージに書かないでください。

## GitHub Pages の公開手順

1. リポジトリの Settings → Pages → Build and deployment → Source を「**GitHub Actions**」にする。
2. main ブランチへ push（または Actions タブから手動実行）すると、`.github/workflows/pages.yml` がテスト実行後に `index.html`・`css/`・`js/`・`data/` を公開します。

## 開発

```bash
node --test                      # 単体テスト（計算・暗号・スキーマ・CLI）
python3 -m http.server 8000      # http://localhost:8000/ で確認（crypto.subtle は localhost/HTTPS で動作）
```

構成: `js/calc`（純粋関数の計算）、`js/data`（制度値・目安・初期値）、`js/model`（検証・設定スキーマ）、`js/crypto`（暗号、ブラウザと Node 共通）、`js/ui`・`js/chart.js`・`js/main.js`（画面）、`scripts/`（CLI）、`test/`。

## 判断の記録

- 手付金は自己資金の内訳（物件価格から差し引かない）。自己資金は既定で「必要資金−借入額」の自動算出、手入力も可。
- 入力欄は `type="text"` と `inputmode` を併用（全角・カンマの正規化と iPhone のテンキー表示のため）。
- 同梱 JSON はマイ設定を開いたときに取得（起動を遅くしない）。取得失敗でもアプリは動作。
- 設定セットの既定値は `js/data/defaults.js` に一本化。
- その他の判断は `docs/requirements.md` 14 章・`docs/implementation-plan.md` 13 章。
