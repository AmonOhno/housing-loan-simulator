# 住宅ローン概算シミュレータ 機能要件定義書

- 文書の版: 1.0（2026-11-15 作成）
- 対象: `housing-loan-simulator`（GitHub Pages で公開する静的 Web アプリ）
- 本書の位置づけ: 設計・実装・テストの拠り所となる要件定義。判断が必要だった点は「14. 未確定事項と判断の記録」に理由とともに残す。
- 本書に記載する金額・金利はすべて一般的な例またはダミー値であり、特定個人の実データではない。

---

## 1. 目的と利用シーン

住宅ローンの本申込（申込書兼保証依頼書）を記入する際に、次の検討を概算で素早く行えるようにする。

1. 申込書の資金計画欄（必要資金＝売買契約金額＋諸経費、調達資金＝借入額＋自己資金）の左右が一致しているかの確認。
2. 「手付金を頭金に回して借入を少なくする」ケースと「手付金相当分も借りて借入を多くする」ケースの比較（毎月返済額・総利息・住宅ローン控除・手元資金の差）。
3. 返済方式、ボーナス返済、保証料方式（一括前払型／金利内包型）、繰上返済による違いの把握。
4. 住宅ローン控除（2026年以降入居の制度）の概算。

想定利用者は住宅ローンを検討中の個人。主な利用端末は iPhone（Safari）。PC ブラウザでも利用できること。

### 1.1 スコープ外

- 金融機関の正式な返済額試算・審査結果の再現（日割り利息、初回・最終回の端数調整の厳密な再現、金利タイプ別の将来金利変動など）。
- 税額の厳密な計算（所得税・住民税そのものの算出）。控除の頭打ちは利用者が入力した税額で簡易に上限をかける。
- ペアローン・連帯債務の持分別計算（単独名義 1 本の借入を対象とする）。
- サーバー側処理、ユーザーアカウント、入力値の外部送信（一切行わない）。

## 2. 用語

| 用語 | 本書での意味 |
|---|---|
| 必要資金 | 物件価格（売買契約金額）＋諸経費 |
| 調達資金 | 借入額＋自己資金 |
| 自己資金 | 借入以外で賄う金額の総額。**支払済みの手付金を含む** |
| 手付金 | 売買契約時に支払済みの金額。決済時に売買代金へ充当される。自己資金の内訳として扱う |
| 決済時必要現金 | 自己資金 − 手付金。引渡し（決済）までに追加で用意する現金 |
| ケース | 借入条件 1 組（借入額・金利・期間・方式など）。最大 3 ケースを並べて比較する |
| マイ設定 | パスワードで暗号化して保存する入力値セット |
| エントリ | 1 つのパスワードで暗号化された暗号文 1 件。中に複数の設定セットを持てる |

## 3. 画面構成（スマホ優先）

単一ページ（`index.html`）。縦スクロール 1 カラムを基本とし、幅 768px 以上では入力と結果を 2 カラムに並べる。

| # | セクション | 内容 |
|---|---|---|
| 1 | ヘッダー | タイトル、「概算です」の短い注意、マイ設定を開くボタン |
| 2 | 共通入力 | 物件価格、諸経費、手付金、税込年収、返済開始年月 |
| 3 | ケース入力 | ケース A／B／C のタブ（スマホ）。ケースの追加（最大 3）・複製・削除。借入額、自己資金、金利、期間、返済方式、ボーナス返済、保証料、繰上返済 |
| 4 | 結果サマリー | 選択中ケースの毎月返済額、ボーナス月加算額、総返済額、総利息、返済負担率 |
| 5 | 資金計画チェック | 申込書の記入イメージ（左：必要資金／右：調達資金）と一致判定 |
| 6 | シナリオ比較 | ケースを列に並べた比較表と、基準ケースとの差額 |
| 7 | 残高推移グラフ | 全ケースの年末残高の折れ線（自前描画の SVG または Canvas） |
| 8 | 住宅ローン控除 | 区分・世帯・入居年の選択、年別控除額と合計、出典の注記 |
| 9 | 年次返済予定表 | 選択中ケースの年ごとの表（折りたたみ可） |
| 10 | マイ設定 | パスワード入力、設定セットの選択・反映、新規作成、編集、エクスポート |
| 11 | 注意書き・出典 | 概算である旨、計算上の前提、制度の出典と確認日 |

### 3.1 UI 要件

- 入力欄は `inputmode="decimal"`／`"numeric"` を指定し、iPhone でテンキーが出ること。フォントサイズは 16px 以上（フォーカス時の自動ズームを避ける）。
- 金額は「万円」単位で入力し、結果は「円」（3 桁区切り）で表示する。大きな金額には「約 3,500 万円」のような読みを添える。
- 入力のたびに即時再計算する（計算ボタンは置かない）。入力途中の不正値では直前の有効な結果を残し、該当欄にエラーを表示する。
- タップ領域は 44×44px 以上。横スクロールが必要な表は表だけを横スクロールさせ、ページ全体は横スクロールさせない。
- ライト／ダークの配色に対応する（`prefers-color-scheme`）。
- 印刷時は入力値と結果が 1 つの流れで読めること（操作ボタンは非表示）。

## 6. 計算仕様

計算はすべて純粋関数モジュール（DOM に依存しない）に実装し、`node --test` で検証する。内部の金額単位は**円（整数）**、金利は年率の小数。

### 6.1 記号

- `P`：借入額（円）、`Pb`：うちボーナス返済分、`Pm = P − Pb`：毎月返済分
- `R`：計算に使う年利（保証料の上乗せ後）、`r = R / 12`：月利、`rb = R / 2`：半年利率
- `n = 借入年数 × 12`：返済回数、`nb = 借入年数 × 2`：ボーナス返済回数

### 6.2 元利均等返済

毎月分の返済額:

```
M = Pm × r × (1 + r)^n / ((1 + r)^n − 1)      （r > 0）
M = Pm / n                                     （r = 0）
```

各回の内訳: 利息 = 毎月分残高 × r、元金 = M − 利息。最終回は残高を全額返済し、返済額 = 残高 + 利息 とする。

検証値: 100 万円・年 1.2%・35 年 → `M` = 2,917.02… → **2,917 円**。

### 6.3 元金均等返済

```
毎月の元金 = Pm / n（円未満切り捨て。端数は最終回で調整）
k 回目の利息 = k 回目の返済前の毎月分残高 × r
k 回目の返済額 = 毎月の元金 + 利息
```

### 6.4 ボーナス返済

一般的な方式に合わせ、借入額を「毎月返済分 `Pm`」と「ボーナス返済分 `Pb`」に分け、別々に計算して合算する。

- ボーナス返済分は **6 か月を 1 期間とし、半年利率 `rb = R / 2`、回数 `nb` 回**の返済として計算する（半年ごとに利息が付く形になるため、月次計算より利息がわずかに多くなる）。
- 元利均等: `B = Pb × rb × (1 + rb)^nb / ((1 + rb)^nb − 1)`（`rb = 0` のときは `Pb / nb`）。
- 元金均等: 1 回の元金 = `Pb / nb`、利息 = ボーナス分残高 × `rb`。
- ボーナス返済は返済開始から **6, 12, 18, … 回目**の毎月返済と同じ月に加算されるものとする（実際のボーナス月の指定や、初回までの期間が 6 か月に満たない場合の日割り・月割り利息は扱わない）。
- チェック: `Pb ≤ P × 50%`。超えた場合はエラー。
- 入力は「ボーナス返済分の借入額」とする。1 回あたりの加算額は出力として表示する。

### 6.5 保証料

| 方式 | 計算上の扱い |
|---|---|
| 金利内包型 | `R = 入力金利 + 上乗せ幅`（「上乗せ済み」を選んだ場合は `R = 入力金利`）。保証料としての別払いは 0 円 |
| 一括前払型 | `R = 入力金利`。一括保証料を**諸経費に加算**し、必要資金に含める。総支払額にも加える |
| なし | `R = 入力金利`。保証料 0 円 |

- 諸経費の入力欄 `expenses` は「一括保証料を除く」金額とし、一括前払型では `諸経費合計 = expenses + 一括保証料` として資金計画に反映する。二重計上を防ぐため、入力欄の説明文にこの点を明記する。
- 初期値は**一般的な目安であり、金融機関・保証会社・審査結果によって異なる。必ず金融機関の提示額に置き換えること**を画面に明記する。特定の金融機関の料率を示すものではない。

**初期値（目安・要確認）**

- 金利内包型の上乗せ幅: **年 0.2%**（一般に 0.2% 前後とされる例が多い）。
- 一括前払型: 借入 100 万円あたりの目安額（元利均等の場合の一般的な例）。借入期間で補間し、`借入額（100 万円単位）× 単価` で算出、1,000 円未満を四捨五入する。

| 借入期間 | 100 万円あたりの目安 | 1,000 万円あたり |
|---|---|---|
| 10 年 | 約 8,500 円 | 約 8.5 万円 |
| 15 年 | 約 12,000 円 | 約 12 万円 |
| 20 年 | 約 14,800 円 | 約 15 万円 |
| 25 年 | 約 17,300 円 | 約 17 万円 |
| 30 年 | 約 19,100 円 | 約 19 万円 |
| 35 年 | 約 20,600 円 | **約 20 万円前後** |

  - 表にない期間は前後の値を線形補間する。10 年未満は 10 年の単価を期間比で按分、35 年超は 35 年の単価を使い「目安の範囲外」と注記する。
  - この表は公表されている一般的な水準を丸めた目安であり、出典を特定の金融機関に帰さない。実額は手入力で上書きする。
  - 繰上返済時の保証料返戻は扱わない。

### 6.6 返済負担率

```
返済負担率（%） = 年間返済額 ÷ 税込年収 × 100
年間返済額 = 返済開始から 12 か月間の返済額合計（毎月返済 12 回 + ボーナス加算 2 回）
```

- 小数第 2 位を四捨五入して小数第 1 位まで表示する。
- 元金均等は返済額が最も大きい初年度の値になる。
- 本ツールの値は**適用金利での返済額**によるもの。金融機関の審査では審査用の金利や他の借入を含めて計算されることがあるため、審査上の返済負担率とは一致しない旨を注記する。
- 目安の色分け: 25% 以下＝通常表示、25% 超 35% 以下＝注意、35% 超＝警告（一般的な目安であり審査基準ではない旨を併記）。

### 6.7 年次返済予定表の作り方

1. 月次の返済予定（回・年月・返済額・元金・利息・残高）を 1 回目から完済まで生成する。1 回目の年月は `startYm`。
2. 暦年（1〜12 月）で集計して年次表にする。年末残高は、その年の 12 月の返済後の残高（12 月に返済がない年は直近の残高）。
3. 残高は毎月分残高とボーナス分残高の合計。

### 6.8 繰上返済

- 実行時期は「返済開始から `afterYears` 年 `afterMonths` か月後」＝ `k = afterYears × 12 + afterMonths` 回目の返済直後とする。
- 繰上返済額は全額を元金に充当する。毎月返済分とボーナス返済分には**その時点の残高比で按分**する（手数料・経過利息・保証料返戻は扱わない）。
- **期間短縮型**: 返済額（毎月額・ボーナス加算額）を変えず、減った残高で以後の予定を作り直す。最終回は残高全額と利息を返済する。短縮される期間は「当初の最終回 − 新しい最終回」（月数）として表示する。金融機関の実務（返済予定表の元金の回数分だけ充当し端数が出ない方式）とは一致しないことがある。
- **返済額軽減型**: 完済時期を変えず、残り回数で返済額を再計算する（元利均等は 6.2・6.4 の式に残高・残り回数を入れる。元金均等は毎月の元金を残高 ÷ 残り回数にする）。
- 複数件は実行時期の早い順に適用する。同じ時期が重なった場合は入力順。
- 効果の表示: 繰上返済なしの総利息との差（利息軽減額）、短縮期間または軽減後の返済額。

### 6.9 端数処理

| 対象 | 処理 |
|---|---|
| 入力（万円）→ 内部（円） | × 10,000。小数入力（例 3,500.5 万円）は円未満四捨五入 |
| 毎月返済額・ボーナス加算額（元利均等） | 円未満**切り捨て** |
| 各回の利息 | 円未満切り捨て |
| 元金均等の毎回の元金 | 円未満切り捨て |
| 最終回 | 残高を全額返済（端数はここで調整） |
| 総返済額・総利息 | 月次予定の合計（丸め後の値の合計） |
| 住宅ローン控除額（各年） | 100 円未満切り捨て |
| 返済負担率 | 小数第 1 位まで（第 2 位四捨五入） |
| 表示 | 円は整数 3 桁区切り。万円表示は小数第 1 位まで |

金融機関ごとに端数処理は異なるため、実際の返済額と数円〜数十円ずれることがある旨を注記する。

## 7. 資金計画の左右一致チェック

### 7.1 定義

```
必要資金 = 物件価格（売買契約金額） + 諸経費合計
諸経費合計 = 諸経費（一括保証料を除く） + 一括保証料（一括前払型のときのみ）
調達資金 = 借入額 + 自己資金
自己資金 = 手付金（支払済み） + 決済時必要現金
差額 = 調達資金 − 必要資金
```

**手付金の扱い（本ツールの定義）**

- 手付金は売買契約時に**自己資金から支払済み**で、決済時に売買代金の一部に充当されるものとする。
- したがって手付金は「自己資金」の内訳であり、必要資金側の物件価格には手付金相当分が含まれたまま（物件価格から差し引かない）。
- 「手付金を頭金に回す」＝自己資金に手付金を含めたまま借入額を抑える。
- 「手付金分も借りる」＝借入額を手付金相当分だけ増やす。資金計画上は自己資金がその分減り、支払済みの手付金相当額は決済時に手元に残る（戻る）形になる。
- `決済時必要現金 = 自己資金 − 手付金`。**負の値になった場合**は「手付金のうち ○ 万円が手元に戻る計算」と表示する（借入額が『必要資金 − 手付金』を超えている状態）。
- 借入額 ＞ 必要資金 の場合は警告（自己資金がマイナスになるため申込書として成立しない）。

### 7.2 自己資金の決め方

- **自動（初期値）**: `自己資金 = 必要資金 − 借入額`。常に左右一致する。借入額を変えると自己資金と決済時必要現金が連動する。
- **手入力**: 申込書に書く予定の自己資金を入力し、差額を判定する。「差額を自己資金に反映」ボタンで一致させられる。

### 7.3 表示（申込書の記入イメージ）

| 必要資金 | 金額 | 調達資金 | 金額 |
|---|---|---|---|
| 売買契約金額 | 3,800 万円 | 借入額 | 3,500 万円 |
| 諸経費 | 150 万円 | 自己資金 | 450 万円 |
| | | （うち手付金 支払済み） | （100 万円） |
| | | （うち決済時必要現金） | （350 万円） |
| **合計** | **3,950 万円** | **合計** | **3,950 万円** |

- 判定: 差額 0 円 →「一致」。0 でない →「調達資金が ○ 万円 不足／超過」を目立つ色とアイコン・文言で表示（色だけに頼らない）。
- ケースごとに表示を切り替えられること。比較表にも「自己資金」「決済時必要現金」の行を出す。
- 実際の申込書の項目名・内訳は金融機関の様式に従う旨を注記する。

## 9. 住宅ローン控除の概算仕様

### 9.1 計算

各年（入居年を 1 年目として控除期間の年数分）について:

```
対象残高 = min(年末残高, 借入限度額)
控除可能額 = 対象残高 × 控除率（100 円未満切り捨て）
所得税からの控除 = min(控除可能額, 所得税額)                 ※所得税額が空欄なら控除可能額の全額
住民税からの控除 = min(控除可能額 − 所得税からの控除, 住民税からの控除上限)
その年の控除額 = 所得税からの控除 + 住民税からの控除
```

- 年末残高は 6.7 の暦年末残高。入居年は `dedMoveInYear`、返済開始が入居年の翌年になる場合、入居年の年末残高は借入額とする。
- 所得税額・住民税上限は全年で同じ値を使う簡易扱い（年収の変化は考慮しない）。
- 住民税からの控除上限の初期値は 9.75 万円（97,500 円）。正確には「所得税の課税総所得金額等の 5%（最高 9.75 万円）」なので、該当額が小さい場合は利用者が上書きする。
- 出力: 年別控除額、控除合計、頭打ちが発生した年の表示（「借入限度額で頭打ち」「税額で頭打ち」）。
- 合計所得金額の要件、床面積要件、取得対価を超える借入の扱い等は判定しない（注記のみ）。

## 10. マイ設定（パスワード保護された設定セット）

### 10.1 機能

1. **読み込み**: パスワードを入力すると、リポジトリ同梱の `data/presets.enc.json` と localStorage 内のエントリを順に復号し、復号できたエントリの設定セットを一覧表示する。選択すると共通項目とケース配列（複数ケース）を入力欄に反映する。
2. **新規作成**: 現在の入力値（共通＋全ケース）に名前を付け、新しいパスワードで新しいエントリとして暗号化する。
3. **既存エントリの編集**: 復号済みのエントリに対して、設定セットの追加・上書き・名前変更・削除ができ、同じパスワードで再暗号化する（ソルトと IV は毎回新しく生成する）。
4. **パスワード変更**: 復号済みのエントリを新しいパスワードで再暗号化する。
5. **保存先**: (a) localStorage に暗号化したまま保存、(b) 暗号化済み JSON としてエクスポート（ファイルのダウンロードとクリップボードへのコピー）。エクスポートは「リポジトリの `data/presets.enc.json` にそのまま置き換えられる全体形式」と「追加分のエントリのみ」の両方を選べる。
6. **削除**: localStorage 内のエントリを削除できる。リポジトリ同梱のエントリはブラウザからは削除できない（リポジトリ側で消す）旨を表示する。

### 10.2 暗号方式

| 項目 | 仕様 |
|---|---|
| API | Web Crypto API（`globalThis.crypto.subtle`）。ブラウザと Node で同じモジュールを使う |
| 鍵導出 | PBKDF2-HMAC-SHA-256、反復回数 **600,000 回以上**（初期値 600,000）、ソルト 16 バイト（乱数） |
| 暗号化 | AES-GCM 256 ビット、IV 12 バイト（乱数）、認証タグ 128 ビット（暗号文末尾に連結） |
| 追加認証データ（AAD） | 固定文字列 `housing-loan-simulator/presets/v1` の UTF-8 バイト列 |
| パスワードの前処理 | Unicode NFKC 正規化のうえ UTF-8 でエンコード。前後の空白は除去しない |
| 平文 | 10.4 の JSON を UTF-8 でエンコードしたもの |
| 乱数 | `crypto.getRandomValues` |
| 照合 | **復号（GCM の認証）の成否のみで判定**する。パスワードのハッシュ・ヒント・検証用の値は保存しない |

- 読み込み時、`iterations` が 600,000 未満のエントリは復号を試みず拒否する（弱い設定への引き下げを防ぐ）。上限は 10,000,000（処理が極端に長くなるのを防ぐ）。
- `kdf`・`cipher`・`hash` が想定値でないエントリは無視して警告を出す。
- 復号に成功したエントリのパスワードは、編集のためにページを開いている間だけメモリに保持する。localStorage・URL・ログには書かない。「ロック」操作またはページを閉じると破棄する。

### 10.3 暗号化データ形式（`data/presets.enc.json`、localStorage も同形式）

```json
{
  "format": "housing-loan-simulator/presets",
  "version": 1,
  "entries": [
    {
      "id": "b64url-12bytes-random",
      "kdf": "PBKDF2",
      "hash": "SHA-256",
      "iterations": 600000,
      "salt": "base64(16 bytes)",
      "cipher": "AES-GCM",
      "iv": "base64(12 bytes)",
      "ciphertext": "base64(暗号文 + 16 バイトの認証タグ)"
    }
  ]
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `format` | 文字列 | 固定値。ファイル種別の識別 |
| `version` | 整数 | 暗号化コンテナ形式の版。現在 1 |
| `entries` | 配列 | 0 件以上。各要素が 1 パスワード分の暗号文 |
| `entries[].id` | 文字列 | ランダムな識別子（内容やパスワードから導出しない）。マージ時の重複判定に使う |
| `entries[].kdf` / `hash` / `iterations` / `salt` | — | 鍵導出のパラメータ |
| `entries[].cipher` / `iv` / `ciphertext` | — | 暗号化のパラメータと暗号文 |

- バイナリ値はすべて標準 base64（パディングあり）。
- **平文のメタデータ（セット名、作成日時、持ち主を示すラベルなど）はコンテナに置かない**。内容の手がかりを公開リポジトリに残さないため。名前や更新日時は暗号文の内側に持つ。
- 初期状態のリポジトリには `{"format": …, "version": 1, "entries": []}` を置けること（エントリ 0 件でもアプリは正常に動く）。ファイルが存在しない・取得に失敗した場合も、localStorage のエントリだけで動作する。

  "sets": [
    {
      "name": "設定セットの名前",

      "common": {

- 上の値は公開ページの初期値と同じ一般例である。

- 読み込み時は未知のフィールドを無視し、欠けたフィールドは画面の初期値で補う（将来の項目追加に備える）。`schemaVersion` が未知の大きい値なら警告を出して読める範囲で反映する。
- 反映時は 4 章のバリデーションを通す（壊れた値や範囲外の値をそのまま入力欄に入れない）。

### 10.5 localStorage

| キー | 内容 |
|---|---|
| `hls.presets.v1` | 10.3 と同じ形式の JSON 文字列（暗号文のみ） |

- 読み込み時の統合: リポジトリ同梱のエントリと localStorage のエントリを合わせて復号を試す。`id` が同じエントリが両方で復号できた場合は、平文の `updatedAt` が新しい方を採用する。
- リポジトリ同梱のエントリを編集した場合、同じ `id` のまま localStorage に保存する（この端末では編集後の内容が優先される）。全端末に反映するにはエクスポートしてリポジトリのファイルを更新する。
- localStorage が使えない環境（プライベートブラウズ等）では例外を握りつぶさずに「この端末には保存できません。エクスポートを使ってください」と表示する。
- **入力欄の値そのものは自動保存しない**（マイ設定から読み込んだ値が平文で端末に残るのを避けるため）。

### 10.6 エクスポートとリポジトリへの反映

- 全体形式のエクスポートは、「リポジトリ同梱のエントリ（編集したものは編集後）＋ localStorage のエントリ」を `id` で重複排除した 1 つの JSON。`data/presets.enc.json` に上書きしてコミットすれば全端末で使える。
- Node スクリプト（`scripts/encrypt-preset.mjs`）でも同じ形式を生成・マージできること。スクリプトはパスワードと平文 JSON を標準入力または環境変数から受け取り、平文をファイルに書かず、コマンドライン引数でパスワードを受け取らない。ブラウザと同じ crypto モジュールを使う。
- 手順（新規作成、追加、パスワード変更、リポジトリへの反映）は README に記載する。

### 10.7 セキュリティ上の注意（画面と README に記載）

- 暗号文は公開リポジトリに置かれるため、誰でも入手してオフラインで総当たりを試せる。**4 桁の数字など短いパスワードは容易に破られる**。8 文字以上で英字と数字を混ぜることを推奨し、新規作成時に 8 文字未満・単一文字種の場合は警告を出す（作成自体は妨げない）。
- 一度コミットした暗号文は git の履歴に残る。パスワードを変更しても、過去の暗号文は古いパスワードで復号できる。
- パスワードを忘れた場合、復元する手段はない。
- パスワード・平文の値は、コード・コメント・テスト・ドキュメント・コミットメッセージのいずれにも書かない。テストはダミーのパスワードと値のみを使う。

## 11. 注意書き（画面に常時または該当箇所に表示）

1. 本ツールの結果はすべて**概算**であり、金融機関の正式な試算・審査結果・契約内容とは異なる。実際の返済額は金融機関の返済予定表で確認すること。
2. 金利は全期間一定として計算している。変動金利・固定期間選択型の将来の金利変動は反映しない。
3. 利息は月割り・半年割りで計算し、日割り計算、初回・最終回の調整、金融機関ごとの端数処理は再現していない。
4. 保証料の初期値は一般的な目安であり、金融機関・保証会社・審査結果により異なる。金融機関の提示額に置き換えること。
5. 返済負担率は入力した年収と適用金利による参考値で、審査上の基準とは異なる。
6. 住宅ローン控除は制度の概要に基づく簡易計算であり、適用可否・控除額を保証しない。要件（所得・床面積・省エネ性能の証明書類・入居時期など）と最新の制度は国土交通省・国税庁・税務署で確認すること。出典 URL と確認日（2026-11-15）を表示する。
7. 入力内容は外部に送信されない。マイ設定はパスワードで暗号化して保存されるが、短いパスワードは破られうる。

## 14. 未確定事項と判断の記録

### 14.1 判断したこと

| # | 論点 | 判断 | 理由 |
|---|---|---|---|
| J1 | 手付金の扱い | 支払済みの自己資金の内訳とし、物件価格からは引かない | 申込書の「必要資金＝売買契約金額＋諸経費」の形をそのまま再現でき、「頭金に回す／その分も借りる」を借入額の違いだけで比較できる |
| J2 | 自己資金の入力 | 初期値は自動（必要資金 − 借入額）、手入力も可 | ケース比較では借入額だけを変えたい。申込書の記入値の検算には手入力が必要 |
| J3 | 共通とケースの分け方 | 物件・年収・控除設定は共通、借入条件はケースごと | 同じ物件で借入条件を比べるのが主目的。物件が違う比較はマイ設定のセットを分ける |
| J4 | ボーナス返済の入力 | 「ボーナス返済分の借入額」を入力 | 申込書の記入形式と「借入額の 50% 以内」チェックに直接対応する |
| J5 | ボーナス月 | 返済開始から 6 か月ごと。月の指定なし | 概算では差が小さい。初回の日割り等は金融機関ごとに異なる |
| J6 | ボーナス分の利率 | 年利 ÷ 2 を半年利率とする | 国内の住宅ローンで一般的な計算方法 |
| J7 | 端数処理 | 返済額・利息とも円未満切り捨て、最終回で調整 | 一般的な処理の 1 つ。金融機関により異なるため注記する |
| J8 | 一括保証料 | 諸経費とは別入力にし、自動で諸経費合計に加算 | 方式を切り替えたときに必要資金が連動し、二重計上を避けられる |
| J9 | 保証料の初期値 | 内包型 +0.2%、一括型は 100 万円あたりの目安表 | 一般に知られた水準。特定金融機関の値とは断定しない |
| J10 | 保証料方式の初期選択 | 金利内包型 | 初期値のまま諸経費 150 万円の例が成り立つ |
| J11 | 繰上返済（期間短縮型） | 返済額を維持して残高から再計算 | 実務の「元金の回数分充当」は返済予定表が必要で入力が複雑になる。概算として十分 |
| J12 | 繰上返済の充当 | 毎月分とボーナス分に残高比で按分 | 利用者に内訳指定を求めないため |
| J13 | 返済負担率 | 適用金利・初年度 12 か月の返済額で計算 | 定義が単純で検算しやすい。審査金利ベースは金融機関ごとに異なる |
| J14 | 控除の年末残高 | 返済開始年月から暦年末の残高を計算 | 経過年数ベースより実際の控除額に近い（初年は返済回数が少ない） |
| J15 | 控除の税額上限 | 所得税額（任意入力）と住民税上限（初期値 9.75 万円）で簡易に頭打ち | ブリーフの指示どおり。税額計算そのものは範囲外 |
| J16 | 控除の初期選択 | 新築・ZEH 水準・子育て世帯等・2027 年入居 | 一般的な例として設定。利用者が物件に合わせて選び直す前提で、区分は証明書類で確認する旨を表示 |
| J17 | コンテナに平文メタデータを置かない | セット名・日時は暗号文の内側 | 公開リポジトリに内容の手がかりを残さない |
| J18 | 1 エントリに複数セット | エントリ＝1 パスワード、内部に `sets` 配列 | 「既存エントリへの設定追加・削除」を素直に実現できる |
| J19 | パスワード照合 | 全エントリに対して復号を試行 | ハッシュ照合を使わない要件を満たす。エントリ数は少数の想定で、所要時間は「エントリ数 × 鍵導出時間」 |
| J20 | 入力値の自動保存 | しない | マイ設定の値が平文で端末に残るのを避ける |
| J21 | AAD と反復回数の下限チェック | 採用 | 形式の取り違えと、弱いパラメータへの差し替えを防ぐ |
| J22 | 初期金利の例 | 年 1.0% | 計算例として切りのよい値。実勢金利を示すものではない |
